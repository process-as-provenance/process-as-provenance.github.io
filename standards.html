04 — Standards Alignment

Semantic Interoperability via W3C PROV-O, CRediT, and RO-Crate

How the provenance graph serializes into standard semantic web ontologies for automated ingestion by Zenodo and academic publishers.

Rather than designing a bespoke format, this system implements established scholarly communication standards. The internal relational model maps directly to W3C PROV-O for fine-grained provenance, ANSI/NISO CRediT for contributor roles, and RO-Crate 1.1 for dataset and manuscript packaging.

W3C PROV-O Mapping Pattern

To record multi-role attribution (Human Accountable Author + AI Content Originator) without violating OWL-DL validation constraints, the system reifies artifact generation using the Qualified Association pattern:

@prefix prov:   <http://www.w3.org/ns/prov#> .
@prefix pav:    <http://purl.org/pav/> .
@prefix credit: <http://credit.niso.org/> .
@prefix onm:    <https://openneuromorphic.org/schema/prov#> .
@prefix ex:     <https://openneuromorphic.org/project/benchmark/> .

# 1. Agents
ex:pi_jane a prov:Person, prov:Agent ;
    prov:actedOnBehalfOf ex:stanford_univ ;
    onm:orcid "https://orcid.org/0000-0002-1825-0097" .

ex:llm_model a prov:SoftwareAgent, prov:Agent ;
    onm:modelName "gpt-4o-2026-05-15" .

# 2. Activity: Manuscript Section Drafting
ex:act_draft_section a prov:Activity ;
    prov:wasInformedBy ex:thread_latency_opt ;
    prov:qualifiedAssociation [
        a prov:Association ;
        prov:agent ex:pi_jane ;
        prov:hadRole onm:AccountableAuthor, credit:writing-original-draft
    ] ;
    prov:qualifiedAssociation [
        a prov:Association ;
        prov:agent ex:llm_model ;
        prov:hadRole onm:ContentOriginator
    ] .

# 3. Artifact: Derived Manuscript Section
ex:sec3_text a prov:Entity ;
    prov:wasGeneratedBy ex:act_draft_section ;
    prov:wasAttributedTo ex:pi_jane ;
    pav:authoredBy ex:pi_jane ;
    pav:createdWith ex:llm_model .

NISO CRediT Attribution Layer

CRediT provides the vocabulary that raw activity logs summarize into. Rather than relying on simple message counters, milestone activities allow contributors to tag specific CRediT roles (e.g., Conceptualization, Software, Formal Analysis, Writing - Review & Editing), generating an empirical contribution matrix for journal submission.

RO-Crate 1.1 Packaging for Zenodo

When a milestone is closed, the system packages the message history, code diffs, and PROV-O JSON-LD graph into an RO-Crate archive (ro-crate-metadata.json). This package is deposited via Zenodo REST APIs to receive a persistent DOI for direct citation in journal reference lists.

Because a minted DOI and its SHA-256-checksummed bundle are treated as permanent, packaging is preceded by a human sign-off on the exact drafted contents (the Editorial Gate; see 02 — What Already Exists). This pre-publication review is the primary safeguard. What happens when a privacy problem surfaces only after a bundle is already public is a distinct, harder problem — checksummed immutability and any promise of redaction pull in opposite directions there, and it is currently open. See 05 — Open Questions.
