03 — The Data Model

PROV-O Primitives, Entity Schemas, and the Accountability Invariant

Standardizing actors, activities, and artifacts directly on W3C PROV-O ontology terms, decoupled across local, federated, and persistent publication scopes.

All research interactions in this platform map to standard W3C PROV-O classes: Activity (threads, decisions, and editorial routing), Agent (human researchers and software models), Entity (messages, code, figures, and datasets), and Bundle (export packages). This vocabulary eliminates naming ambiguities and guarantees semantic interoperability.

1. Thread (`prov:Activity`)

A Thread is a bounded, time-ordered research activity—such as an experimental benchmark, algorithm design debate, or manuscript drafting milestone. It generalizes the existing ThreadEntry ledger record.

2. Agent (`prov:Agent`)

An Agent represents an actor within the system, divided into two explicit subclasses:

  • prov:Person: A verified human researcher, associated with an ORCID, organizational affiliation (prov:Organization), and platform aliases.
  • prov:SoftwareAgent: An AI model, bot, or automated script (e.g., gpt-4o-2026-05-15, claude-3-7-sonnet, or local Ollama instances) operating under human supervision.

Open question, flagged in external review: not every contributor — students and new researchers especially — will hold an ORCID at the time of their contribution. The schema currently treats onm:orcid as the primary binding identifier for prov:Person; a durable fallback identifier (such as a cryptographic public key or verified platform URI) is supported for pre-ORCID contributors.

3. Message (`prov:Entity`)

A Message is the atomic communicative act within a thread. It carries content, timestamp, source platform permalinks, and cryptographic checksums. Invariant: Every Message MUST have a human prov:Person author. No communicative event enters the permanent graph without a human taking responsibility for its submission.

Bot and CI Ingestion Rule: Automated bots (CI test runners, Q&A bots) produce prov:Entity execution outputs generated by a prov:SoftwareAgent, acting on behalf of the human operator who configured the workflow.

4. Artifact (`prov:Entity`) & The Accountability Invariant

An Artifact is a derived scientific deliverable: code diffs, figures, benchmark datasets, or manuscript sections. To resolve journal policies on generative AI, Artifacts enforce a two-tiered attribution pattern:

Attribution FieldPermitted Agent TypeSemantic Definition
accountable_author (pav:authoredBy) prov:Person (Human Only) The researcher ethically and scientifically accountable for introducing and verifying the artifact.
originator (pav:createdWith) prov:Person OR prov:SoftwareAgent The physical generator of the content (human intellect or generative AI model).

5. Decision (`prov:Activity`)

A Decision records a structured consensus milestone within a thread: the formal proposition, voting members, quorum threshold, and selected outcome.

Quorum eligibility, vote weighting, and support for alternative mechanisms (e.g., a private ballot rather than a public reaction) are defined by each lab or consortium. The system is designed to record and surface these signals for a community's own governance process, not to dictate what counts as consensus.

6. Context Bundle & Publication Scopes (`prov:Bundle`)

A Bundle is a self-describing container aggregating a slice of the provenance graph—its constituent threads, messages, decision records, and artifact checksums. Crucially, a Bundle does not presume public deposition. Every Bundle carries an explicit onm:publicationScope property that determines how it is processed, encrypted, and routed:

Scope Enum Graph Serialization Ingestion Target Governance Constraint
onm:ScopePrivateLab Internal SQLite / JSON-LD Local Vector DB / Lab RAG instance Zero external export permissions. Preserves private institutional memory and powers internal LLM drafting without leaks.
onm:ScopeConsortiumFederated CList Feed / ActivityPub / P2P payload Cross-lab aggregator node (e.g., CList peer) Requires multi-party consortium MOU; PII automatically scrubbed. Enables cross-institutional synchronization without public DOIs.
onm:ScopeFunderDigest Summary JSON / Markdown Brief Funder discovery portal / Grant progress feed High-level activity metrics and capability indicators only. Eliminates grant reporting friction and surfaces capabilities to agencies (NSF, NIH).
onm:ScopePublicPersistent RO-Crate 1.1 Zip + DataCite JSON-LD Zenodo / CERN Open Data / Publisher API Mandatory Editorial Gate approval; cryptographic immutability (SHA-256); persistent DOI minting for manuscript citation. 
# Example PROV-O Representation of a Scoped Bundle
@prefix prov:   <http://www.w3.org/ns/prov#> .
@prefix onm:    <https://openneuromorphic.org/schema/prov#> .
@prefix ex:     <https://openneuromorphic.org/project/mri_bench/> .
@prefix xsd:    <http://www.w3.org/2001/XMLSchema#> .

ex:bundle_qa_sprint_w34 a prov:Bundle, prov:Entity ;
    prov:wasGeneratedBy ex:act_weekly_qa_audit ;
    prov:wasAttributedTo ex:pi_sebastien ;
    onm:publicationScope onm:ScopeConsortiumFederated ;
    onm:distributionTarget "clist://node.openneuromorphic.org/feeds/mri_qa" ;
    onm:editorialSignoffStatus "approved_for_federation" .

7. Editorial Gate / Publication Authorization as First-Class Provenance

In earlier drafts, the Editorial Gate was described procedurally (a human review queue) but lacked a formal node in the graph. This left a critical audit gap: who authorized a private lab conversation to become a public or federated record?

The data model now specifies publication authorization as an explicit prov:Activity reified via qualified associations:

ex:act_publication_signoff a prov:Activity ;
    prov:used ex:bundle_qa_sprint_w34 ;
    prov:startedAtTime "2026-10-24T14:30:00Z"^^xsd:dateTime ;
    prov:qualifiedAssociation [
        a prov:Association ;
        prov:agent ex:pi_sebastien ;
        prov:hadRole onm:EditorialAuthorizer, credit:supervision
    ] ;
    onm:targetScopeAuthorized onm:ScopePublicPersistent ;
    onm:resultingArtifact ex:rocrate_mri_qa_zenodo_v1 .
